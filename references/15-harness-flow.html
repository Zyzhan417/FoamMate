证伪「harness 有一个 stdin 入口 / 一个 main() 驱动六步」

        

          
grep -n "input()\|sys.stdin.read\|/dev/stdin" scripts/*.py scripts/*.sh

          
        

        
输出为空 —— 十个脚本没有一个读 stdin。所以「一句话进来」这件事从来没有发生在进程内部：

          每次调用都是 argv 进 → 干活 → stdout + 退出码出。

          对操作系统来说，十个脚本各自就是入口（main() + argparse，或 bash 直接执行）；
          对 agent 来说，入口是那份文档。两种「入口」都不是自然语言入口。

      

    


    

      

        
三个通道 · 其中两个是单向的

        

        
没有 stdin、没有 socket、没有 API、没有共享内存。每一步都是「从磁盘读状态 → 干活 → 往磁盘写状态 → 吐一个退出码」。进程随时死掉都不影响下一步，因为 上下文不在内存里，在文件系统里。

        
agent 判断下一步看的是 退出码，不是 stdout 文字：读到 0 继续，读到 10 停下问人，读到 50 去执行它给的那条 source。stdout 是给人看的，退出码是契约。
