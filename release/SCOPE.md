# SCOPE · 这个 harness 能做什么，不能做什么

一句话：**它是一个以 OpenFOAM v13 为唯一后端的"建 case / 改 case / 跑 / 判门"工具包。**
流程由调用方决定；本包不含模型、不含循环、不含批量入口。本文是它的边界声明，出问题时先查这里。

- 版本：`0.3.0`
- 适用范围：OpenFOAM **v13** 单版本
- 许可：**MIT**（见包内 `LICENSE`）

---

## 1 支持（本版本承诺的部分）

| # | 能力 | 输入 | 产物 | 判定依据 |
|---|---|---|---|---|
| 1 | **环境前置检查** | 无参数 | 6 项检查结果，一行一项 | 退 `0` 全过 / `50` 环境不全 / `51` 版本不符 |
| 2 | **需求 → 四元组** | 一句自由文本 | `{geometry, properties, boundary, objective, complete, missing}` | 退 `0` 完成 / `10` 缺项，缺项**不填默认值** |
| 3 | **按关键字检索本机教程** | 一个关键字 | `相对路径:行号` 列表 + `FOUND=` / `SHOWN=` | 退 `0` 有命中 / `11` 无命中（有效结论，不回退到记忆） |
| 4 | **从 tutorial 派生 case** | 教程相对路径 + 目标目录 + 四元组 JSON | 目标目录（逐字节副本）+ `case.meta`（六键） | 退 `0` 成功 / `12` 源不合法（目标目录不创建）/ `13` 目标已存在（不覆盖） |
| 5 | **改字典（人工/宿主决定改什么）** | `foamDictionary` 命令 | 改后的字典 + 回读校验 | 回读不符即按失败处理；entry 必须恰好命中 1 次 |
| 6 | **跑求解** | case 目录 + `--mode check\|short\|full` | `log.blockMesh` / `log.checkMesh` / `log.shortRun` / `log.run` | 退 `0` / `20` 求解失败 / `21` 超时 / `22` 环境缺失 / `23` 无可用网格 |
| 7 | **五道门判定** | case 目录 + `--stage pre\|post` | 每门一行 `G<n> RC=`，日志 `log.g1..g5` | 退 `0` 全过 / `1`–`5` 第一个失败的门 |
| 8 | **失败日志定位与受控回修** | 失败日志（locate）或改动清单（apply） | 一行 JSON（`changes` / `written` / `backup_dir` / `declined` / `reason` / `fingerprint`） | 退 `0` / `31` 到上限 / `32` 指纹重复 / `33` 校验或回读不符 |
| 9 | **单一前处理路径：blockMesh** | 派生源自带 `system/blockMeshDict` | 网格 + `log.blockMesh` | G2 见 `Mesh OK.` |
| 10 | **单一前处理路径：导入外部网格** | `gmshToFoam`（ascii `.msh`）/ `fluent3DMeshToFoam` | 网格；patch 名以 `constant/polyMesh/boundary` 为准 | G1 判 patch 集合一致 |
| 11 | **批量运行（v0.2 新增）** | `cases.json`（base + vary 参数矩阵）+ `batch.py` | `runs/<批次>/<case_id>/` 每例一个目录 + `runs/<批次>/results.csv`（15 列） | 退 `0` 全 pass / `70` 有例失败但整批跑完 / `71` 整批中止 / `64` 用法错误 |
| 12 | **2D 三角形网格导入（v0.2 新增）** | gmsh `-2` 产出的 ascii `.msh`（msh2）+ `msh2d_to_foam.py` | 单层三棱柱 `constant/polyMesh`（`empty` 面数 == 2×cells） | 退 `0` 成功 / `14` msh 不合规或自检不过（一个文件都不写）/ `15` 输出目录非空且未 `--force` |
| 13 | **二次开发 / 用户库（v0.3 新增）** | 系统子库目录 + 目标副本 + 库名 + 允许改动的 glob + `dev_lib.py` | 用户副本（`$WM_PROJECT_USER_DIR/src/<名>`）+ `lib<名>.so` 落在 `$FOAM_USER_LIBBIN` | `prepare` 退 `85` / `check` 退 `86` / `build` 退 `87` / `verify` 退 `88`（`dlopen error` 计数非 0）或退 `89`（系统树被改）。**只保证编译与加载，不保证物理正确** |

**支持的意思是**：这条路我们逐条跑过、判据是机械可判定的、失败有明确退出码与下一步。
不支持任何"大概能行"的用法。

## 2 不支持（本版本明确不做，别试）

| # | 不支持 | 为什么 / 替代做法 |
|---|---|---|
| 1 | **批量的"智能"部分** | 批量入口有了（§1 第 11 条），但它**只按给定值改参数**：参数位置 `{file, entry}` 必须自己写全、尺寸扫描只能走 `convertToMeters` 这类标量、改 `vertices` 表等结构改动一律不支持（`{file, entry, new_value}` 表达不了）。"改成什么值"永远是你的决定。 |
| 2 | **二次开发里「改 C++」那一步、以及物理正确性** | 派生 / 判范围 / 编译 / 加载证明在包内（§1 第 13 条，用法见 `SKILL.md` §11），但那四步只回答"这个 `.so` 能被 v13 加载"。改 `.C`/`.H` 由人 / 宿主做，改得对不对没有门能判——同 §5。**`/opt/openfoam13` 一个字都不改**：副本只放在 `$WM_PROJECT_USER_DIR` 下。 |
| 3 | **`snappyHexMesh` / STL / CAD** | 前处理只有 §1 的第 9、10 两条路。曲面、多体装配、边界层加密、STL 输入一律**停下问人**，不要自己生成几何、不要写脚本操作 STL。 |
| 4 | **GUI / Web 界面** | 全部交互是命令行。没有浏览器端、没有图形化参数面板。 |
| 5 | **多版本 OpenFOAM** | 见 §3。v11/v12、v2012、esi 系、OpenFOAM.com 一律不测、不装、不适配。 |
| 6 | **物理正确性判定** | 见 §5。门只判"能不能跑"，不判"结果对不对"。 |
| 7 | **检索层 / 向量库 / MCP** | 知识入口只有 `find_template.sh` 一个 grep。不建索引、不绑语料版本。 |
| 8 | **自动改字典** | `fix_case.py` 的 `locate` 只回答"改哪个文件的哪个 entry"，永远给 `new_value: null`；"改成什么值"依赖需求与物理判断，由调用方决定。 |
| 9 | **元数据自动维护** | `case.meta` 的 `changes` 不会自动更新，需要人/宿主按实际改动写。 |

## 3 v13-only（这条是硬的）

| 项 | 值 |
|---|---|
| 支持的版本 | `WM_PROJECT_VERSION` 字面等于 `13` |
| 不支持 | v12 及更早、v2012、esi 系、OpenFOAM.com 任何版本、`tutorials/legacy/` 下的旧式算例 |
| 怎么被判出来 | 前置检查第 4 项；不符退 `51`（与"环境没加载"的 `50` 分开：前者要换安装，后者只要一条 `source`） |
| 为什么不做多版本 | 判据要跟着版本分叉，判据分叉就会同时出现假红与假绿——同一份日志在两个版本下结论相反，而"能不能跑"这句话就不再有意义。宁可少支持，不要说不清 |

`tutorials/legacy/` 里的 case（旧式 `icoFoam` 等、`controlDict` 不带 `solver` 条目）**不要**当派生源：
它们与 v13 主线语法不同，派生出来的算例常常直接 FATAL，或者更糟——悄悄用了旧逻辑。

## 4 已知限制

1. **几何能力上限低**：`blockMesh` 表达不了曲面与复杂装配。这是刻意取舍，不是待办。
2. **`checkMesh` 通过 ≠ 物理正确**：五道门只保证"能跑、边界齐、场可读"。
3. **v13 语法与旧教程不兼容**：必须在本机源码/教程树里 grep 确认，不能凭印象写字典。
4. **导入网格的 patch 名不可预测**：`gmshToFoam` 之后必须读 `constant/polyMesh/boundary` 拿真实
   patch 名再写 `0/`，不能假设 `inlet` / `wall` 存在。
5. **低分辨率下的高雷诺数没有可信度**：几何不变、只把粘度调到很小，算例照样能过门（实测
   20×20 网格、`nu=1e-06` 五门全绿），但那个结果没有物理意义。门不拦这件事，只有你知道自己在做什么。
6. **并行与内存**：本机内存有限（历史上有 OOM 事故）。默认串行；不提供并发参数。
7. **日志是唯一证据**：`log.*` 被删/被覆盖后，门就只能重新跑一遍才能判；`--stage post` 不跑求解，
   它读的是上一步写下的日志。
8. **脚本头部注释里的 `references/…`、`bench/…` 是开发期设计文档，不在本包内**。它们只出现在
   注释里，不影响运行；想知道某个判据为什么这么定，看本包的 `SKILL.md` 与 `QUICKSTART.md`。
9. **`objective` 只被记录，不被执行**：需求写"稳态"并不会让 harness 去改 `ddtSchemes`。
   后置门禁会打一行 `OBJ=<match|mismatch|unknown>` 把"要的"与"实际的"并排显示，
   但**它不改变退出码**——判据是不是满足，需要你按物理判断。这是本包最容易被误读的一条：
   五道门全绿只意味着"能跑"，不意味着需求全中。
10. **几何尺寸不会被需求校验**：需求只说"二维方腔"时，边长静默继承派生源的 `convertToMeters`。
    后置门禁打 `GEO=`（网格量+尺度）、`RE=`（估的雷诺数）、`RES=<coarse|marginal|ok>`（网格够不够），
    同样**不是门、不改退出码**。实测例：400 cells + Re=1e5 五门全绿，但末时刻内部 |U|max≈0.17 m/s
    （顶盖 1 m/s），是 Stokes 流量级——**流程完全正确，结果没有物理意义**。
    本包不做网格无关性验证，也不判断 Re 是否可解。
11. **改网格必须删 `constant/polyMesh`**：`run_case.sh` 只在网格不存在时才 `blockMesh`。
    只改 `blockMeshDict` 等于什么都没发生，且 `G2` 会用上一次的 `checkMesh` 日志照样通过
    （`Mesh OK.` 还在里面）。只有后置门禁的 `RES=stale` 会说破，而**它不在退出码里**。
12. **2D 网格只能是单层棱柱**：OpenFOAM 的 2D 判据要求 `empty` 面数 == 2×cells 且所有边垂直或
    平行于非空方向，只有三棱柱满足。`msh2d_to_foam.py` 因此把 2D 三角面拉成一层棱柱；单层四面体
    （`gmsh -3` 对三角面挤出的默认结果）会 checkMesh 红，且实测在 `t=0.04 s` 发散。
    真正的 3D 四面体网格是另一条路（`gmshToFoam` 直接收），不在本转换器的范围内。
13. **所有诊断行都不改变退出码**（`OBJ=` / `GEO=` / `RE=` / `RES=` 全部如此）。
    按"只看退出码"自动化的调用方需要自己 grep 这些行。
    如果你要的是"结果可信才返回 0"，本包不给这个保证，也不打算给——它判不了物理。

## 5 不保证物理正确性

五道门回答的是三个问题：**结构齐不齐**（G1）、**网格合格不合格**（G2）、**跑不跑得完、
场读不读得出**（G3/G4）、**有没有越界改文件**（G5）。它们**不回答**：

- 结果与实验/解析解/文献是否一致；
- 湍流模型、边界条件、时间步是否适合这个物理问题；
- 网格是否足够细到能分辨你关心的结构。

要做到这些，你需要自己给参照值（实验数据、解析解、已发表的算例）并自己比对——本包不含
参照值，也不含"断言层"。**说"这个算例算对了"必须由你负责，不能引用本包的退出码。**
